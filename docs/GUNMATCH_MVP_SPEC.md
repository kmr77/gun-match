# GunMatch MVP仕様・実装照合

更新日：2026-11-05（GM-028個人情報・退会整合性確認）
対象：GunMatch Laravelプロジェクトのみ
照合基準：2026年10月のGunMatch専用作業資料、後続のGunMatch作業指示、GM-025の確認事項。既存コードの状態を仕様の根拠にはしない。

## 仕様の状態

- **確定**：GunMatch資料または明示された作業指示に根拠がある要件。
- **後から変更・追加された確定事項**：10月以降の明示的な作業指示で追加された要件。
- **未確定**：既存資料だけでは決められず、運営判断・契約・法的確認が必要な事項。
- **実装済み／未実装**：コード・DB・テストで確認した現在の実装状態。仕様の確定とは別に記録する。
- **仕様不一致**：確定要件とGM-024までの実装に差があり、GM-025で是正する対象。

## 認証状態と利用可能範囲（GM-026で確定）

| 状態 | 利用可能範囲 |
| --- | --- |
| 未ログイン | 公開ページ、登録・ログイン |
| ログイン済み・メール未確認 | メール確認とプロフィール補完のみ。会員機能・管理機能は利用不可 |
| メール確認済み・電話番号未登録 | プロフィールで電話番号を補完し、SMS確認へ進める。通常の会員・管理機能は利用不可 |
| メール確認済み・電話未確認 | SMSコードの送信・検証のみ。通常の会員・管理機能は利用不可 |
| メール・電話とも確認済み | 有効な一般会員は会員機能、管理者権限のある会員は管理機能を利用可能 |
| 利用停止中 | 既存仕様どおり、認証状態にかかわらず利用不可。セッションを無効化 |

プロフィール補完とメール確認ページは認証未完了でも利用できます。本番の管理者も同じく電話確認が必要で、認証未完了の間は管理画面へ入れません。ローカル開発環境に限り、メール確認済み・有効・管理者権限の既存管理者は `/admin` を操作できますが、通常の会員機能はSMS確認まで利用できません。このローカル運用上の猶予は `APP_ENV=local` のみで有効です。本番環境には迂回を設けません。既存管理者の安全な移行には、SMS事業者とアダプターを先に準備し、ステージングで登録・送信・再送・確認・失敗時の一連の動作を検証した後に本番へ反映します。既存管理者は本番反映後、プロフィールで電話番号を補完し、管理画面を使う前にメール・電話確認を完了します。SMS事業者未設定の状態で認証ゲートを本番反映しないでください。管理者を手動で確認済みにする迂回手段は設けません。

- 表示名と本名の区別が画面・DB上で不明確だった。

## GM-026で確定・実装した認証条件

- メール認証とSMSによる電話確認の両方を通常利用の条件とする。
- SMSコードは暗号学的乱数で生成し、ハッシュだけをDBに保存する。5分で失効し、1回だけ使用できる。
- 送信間隔（60秒）、アカウントごとの送信回数（1時間に5回）、入力試行（コードごとに5回）を制限し、再送時は旧コードを無効化する。
- 電話番号変更時は確認日時と既存チャレンジを無効化し、再確認を要求する。チャレンジ表には電話番号自体を重複保存せず、比較用ハッシュを保持する。
- SMS送信事業者は未選定、実配送は未実装。偽送信Gatewayは自動テスト内のみで使用し、本番アプリの既定Gatewayは送信を拒否する。
- SMS確認は本人確認・事業者確認審査や所持許可の確認を意味しない。

## GM-027で是正した表示上の不一致

- TOPの「マーケットプレイス」「新着の譲る／探す」「利用の流れ」は、未実装の掲載・取得希望・マッチングや実際の利用手順が提供中であるとの誤認を招く表示でした。ブランド紹介と基本姿勢の表示に改め、カードは架空のデザイン確認用サンプルと明記しています。銃器等の掲載・検索・譲渡・取得募集・マッチング機能は引き続き未実装です。
- FAQが運営問い合わせフォーム未提供と案内していましたが、`/contact` は一般的な運営問い合わせフォームとして実装済みです。FAQを実態に合わせ、会員間連絡・取引問い合わせには使用できない旨を追記しました。
- 会員メニューのプロフィール表示は本人のみの表示サンプルで、第三者向け公開プロフィールは未実装です。メニュー、ページ名、説明をそのとおり明示しました。通知設定も配信・変更が未実装であることをメニューから明示します。
- ログイン・メール確認・電話確認画面に、未完了時の次の手続きと、SMS事業者未選定のため実配送できない現状を表示します。ローカルのログメールは実配送ではないことをメール確認画面に明記します。
- マイページの会員設定では、会員区分、運営による会員確認審査、メール認証、SMSによる電話番号確認を別項目として表示します。所持許可の自己申告・電話番号確認を運営審査済みの意味に使用しません。

## GM-028 個人情報・退会・文書整合性

- 退会は本人パスワードを再確認したうえで `users` 行を削除し、当該ユーザーのDBセッション、パスワード再設定token、SMS確認チャレンジを削除します。現在のセッションはlogout・invalidateし、CSRF tokenを再生成します。削除後の同じメールアドレス・パスワードによるログイン失敗をFeatureテストで確認します。
- 通報と管理操作履歴は退会と同時に消去せず、外部キーの `nullOnDelete` でユーザー参照をnull化して記録本体を残します。通報・問い合わせの自由記述や管理メモ・IPアドレスは、残存記録中に個人を推知できる情報を含む可能性があります。削除期間・匿名化・法的根拠は未確定です。問い合わせは会員行と外部キー連携しておらず、退会で消えません。
- 審査メモは `users` に管理者向け情報として保存し、通常会員表示・`User` の配列シリアライズから秘匿します。管理者が記録した審査方法・日時・状態等は監査履歴にも限定項目で記録し、メモ全文・認証秘密は複製しません。
- SMSチャレンジにはコードハッシュ・電話比較用ハッシュのみを保存し、モデル配列から隠します。ユーザー削除でchallengeを削除します。実SMS配送は引き続き未実装です。
- `/terms`、`/privacy` は準備中の案内で、登録ページからのリンクはあるものの同意取得・同意記録は未実装です。正式な運営者情報、目的、保存期間、委託・第三者提供、本人請求窓口、退会後の保持を確定するまで正式文書として公開しません。
- ローカルの `MAIL_MAILER=log` は宛先と本文をログへ記録し、メール確認・パスワード再設定URLを含む可能性があります。実在会員の宛先で試さず、ログの閲覧権限・保持・消去、本番でlog mailerを無効にする設定を運用確認事項とします。実際の `.env` 内容とログ保持状態は調査していません。
- 個人情報の保存先・アクセス範囲・退会時の扱いと公開前レビュー用文案は [GM-028-privacy-inventory.md](GM-028-privacy-inventory.md) に記録しました。運営者情報、利用目的、保持期間、委託・第三者提供、本人請求窓口等は未確定であり、法務・運営レビュー前に確定情報として公開しません。
- 情報種別ごとの保存先、取得目的、アクセス権、本人修正可否、退会処理、未確定の保存・消去方針は [GM-028個人情報棚卸し・公開前レビュー資料](./GM-028-privacy-inventory.md) に記録しました。これは内部レビュー用で、法務承認済みの公開文書ではありません。
- 本調査ではサービスの最終MVP構想を変更していません。TOP等の現段階の提供範囲表示と将来の確定仕様は別に扱います。
