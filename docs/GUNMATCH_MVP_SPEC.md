## 認証状態と利用可能範囲（GM-026で確定）

| 状態 | 利用可能範囲 |
| --- | --- |
| 未ログイン | 公開ページ、登録・ログイン |
| ログイン済み・メール未確認 | メール確認とプロフィール補完のみ。会員機能・管理機能は利用不可 |
| メール確認済み・電話番号未登録 | プロフィールで電話番号を補完し、SMS確認へ進める。通常の会員・管理機能は利用不可 |
| メール確認済み・電話未確認 | SMSコードの送信・検証のみ。通常の会員・管理機能は利用不可 |
| メール・電話とも確認済み | 有効な一般会員は会員機能、管理者権限のある会員は管理機能を利用可能 |
| 利用停止中 | 既存仕様どおり、認証状態にかかわらず利用不可。セッションを無効化 |

プロフィール補完とメール確認ページは認証未完了でも利用できます。本番の管理者も同じく電話確認が必要で、認証未完了の間は管理画面へ入れません。ローカル開発環境に限り、メール確認済み・有効・管理者権限の既存管理者は `/admin` を操作できますが、通常の会員機能はSMS確認まで利用できません。このローカル運用上の猶予は `APP_ENV=local` のみで有効です。本番環境には迂回を設けません。既存管理者の安全な移行には、SMS事業者とアダプターを先に準備し、ステージングで登録・送信・再送・確認・失敗時の一連の動作を検証した後に本番へ反映します。既存管理者は本番反映後、プロフィールで電話番号を補完し、管理画面を使う前にメール・電話確認を完了します。SMS事業者未設定の状態で認証ゲートを本番反映しないでください。管理者を手動で確認済みにする迂回手段は設けません。

## GM-026で確定・実装した認証条件

- メール認証とSMSによる電話確認の両方を通常利用の条件とする。
- SMSコードは暗号学的乱数で生成し、ハッシュだけをDBに保存する。5分で失効し、1回だけ使用できる。
- 送信間隔（60秒）、アカウントごとの送信回数（1時間に5回）、入力試行（コードごとに5回）を制限し、再送時は旧コードを無効化する。
- 電話番号変更時は確認日時と既存チャレンジを無効化し、再確認を要求する。チャレンジ表には電話番号自体を重複保存せず、比較用ハッシュを保持する。
- SMS送信事業者は未選定、実配送は未実装。偽送信Gatewayは自動テスト内のみで使用し、本番アプリの既定Gatewayは送信を拒否する。
- SMS確認は本人確認・事業者確認審査や所持許可の確認を意味しない。

## GM-028 個人情報・退会・文書整合性

- 退会は本人パスワードを再確認したうえで `users` 行を削除し、当該ユーザーのDBセッション、パスワード再設定token、SMS確認チャレンジを削除します。現在のセッションはlogout・invalidateし、CSRF tokenを再生成します。削除後の同じメールアドレス・パスワードによるログイン失敗をFeatureテストで確認します。
- 通報と管理操作履歴は退会と同時に消去せず、外部キーの `nullOnDelete` でユーザー参照をnull化して記録本体を残します。通報・問い合わせの自由記述や管理メモ・IPアドレスは、残存記録中に個人を推知できる情報を含む可能性があります。削除期間・匿名化・法的根拠は未確定です。問い合わせは会員行と外部キー連携しておらず、退会で消えません。

- SMSチャレンジにはコードハッシュ・電話比較用ハッシュのみを保存し、モデル配列から隠します。ユーザー削除でchallengeを削除します。実SMS配送は引き続き未実装です。

## GM-029 メール配送・認証ログ対策

- メール認証は通常利用開始に必須の確定仕様で、署名付きURLの検証機能は実装済みです。期限切れ・署名不正・他会員宛てリンクの拒否をFeatureテストします。パスワード再設定tokenはハッシュ保存、60分有効、一度利用後に削除します。
- GM-029でローカル／テスト既定mailerを`array`にし、Framework既定の`log`選択も本文をログへ出さない`array` transportへ置換しました。送信エラーは機密情報を含めず一般エラーとして記録し、メール確認・プロフィール変更・登録・再設定画面へ失敗を表示します。送信失敗時に再設定tokenは削除します。log fallbackは設定せず、failoverもSMTPのみです。
- 本番は`MAIL_MAILER=smtp`、SMTP認証、TLS必須、送信元アドレス等が不足する場合にアプリ起動を拒否します。SMTP設定は環境変数から読み込み、認証情報入り`MAIL_URL`は使用しません。さくらインターネット公式資料で初期ドメイン形式、送信ポート587/465、465のSMTPS、SMTP認証およびメールアドレス全体をユーザー名とすることを確認しました（[公式設定](https://help.sakura.ad.jp/mail/2114/)）。587のSMTP暗号化方式は公式資料で確認できていないためSTARTTLS接続が契約環境で確認されるまで使用しません。対象契約の初期ドメイン・メールアカウント、本番接続、実配送は未確認です。今回、外部へのメール送信・契約やメールアカウント作成は行っていません。
- SMS実配送は引き続き未実装です。GM-028で整理した保存期間、退会後の記録保持、正式な規約・プライバシーポリシーの未確定事項はGM-030後も未解決です。登録時同意記録の基盤はGM-030で整備しましたが、規約が準備中のため無効・未運用です。詳細は[GM-028個人情報棚卸し](./GM-028-privacy-inventory.md)を参照してください。

- `terms_consents` は登録フォームで本人が現にチェックした場合のみ、会員ID、版、日時、`registration_checkbox` 操作識別子を保存します。版と公開本文は設定上の現行版で固定し、クライアントから任意版を記録できません。同一会員・同一版は一意で、既存履歴を上書きしません。
- 初期の規約公開設定は無効です。明示的な公開状態・版・発効日時・本文セクションが揃い、有効日以降である場合だけ登録時同意を必須化します。未公開状態への同意投稿は拒否し、同意記録は生成しません。プライバシーポリシーの表示・版は別管理で、同意記録は作成しません。
- 既存会員に同意日時を遡及記録しません。退会時には外部キーcascadeにより同意履歴も削除しますが、退会後の保持期間・法的必要性は未確定で、運営・法務判断を要します。
- GM-028で整理した個人情報保持・削除・退会後記録、正式規約、保存期間、委託・第三者提供等の未確定事項を解消したものではありません。棚卸しは[GM-028個人情報棚卸し](./GM-028-privacy-inventory.md)を参照してください。

## GM-032 会員公開プロフィール

- 公開ページ `/members/{user}` は、利用可能状態でメール・電話確認済みの会員のみ表示します。未認証・停止中・存在しない会員は404です。
- 公開項目は表示名と会員区分（個人会員・銃砲店会員）に限定します。都道府県等を含む追加項目は公開しません。
- 本名、生年月日、電話番号、メールアドレス、所持許可の自己申告、運営による確認状態・審査メモは公開しません。自己申告やSMS確認を運営審査済みとして表示しません。
- `/mypage/profile/public` は本人が公開表示を確認し、公開ページURLへ遷移する画面です。会員の既存情報・権限は変更しません。

## GM-033 サイト内通知

- `member_notifications` は会員・公開お知らせ・既読日時を保持し、会員IDとお知らせIDの一意制約で同一通知の重複を防ぎます。会員またはお知らせ削除時は関連通知をcascade削除します。
- 公開済みお知らせのみ通知対象です。管理者が公開した際に有効会員へ作成し、ページ表示時にも公開済み分を補完するため、公開日時予約後の通知・新規会員も反映されます。DB一意制約により繰り返しアクセスしても重複しません。
- `/mypage/notifications` と既読操作は認証・利用状態・メール認証・電話確認を要求し、本人所有の通知だけを表示・更新します。単件既読・一括既読が可能です。
- メール・SMS配送や会員間の取引・マッチング連絡は含みません。通知は運営のお知らせに限ります。
