# Codexへの指示：GunMatch TOPベースのLaravelへの組み込み

## 作業目的

同梱 `gunmatch-top-starter` をGunMatchの**フロントサイトTOPの基準デザイン**としてLaravelプロジェクトに組み込む。PC/SPの見た目を確認し、今後「一覧」「詳細」「マイページ」を実装できる共通基盤にする。

## 作業前に必ず確認

1. 既存GunMatchリポジトリの状態（ブランチ、git status、変更差分、現在のLaravel版、PHP版、ディレクトリ、既存のルート・認証方式）を調べ、報告する。
2. 既存実装がある場合は**上書きしないで差分を精査**。必要な構造だけ取り込む。
3. この作業はTOPデザインの導入が目的。判断なしにDB構造の大改修、認証実装、決済機能、新機能開発、別CSSフレームワーク導入をしない。

## 使用する資材

- `resources/views/home.blade.php`：TOP
- `resources/views/layouts/app.blade.php`、`partials`、`components`：共通ビュー
- `public/assets/css/gunmatch.css`：外部CSS
- `public/assets/js/gunmatch.js`：外部JavaScript（SPメニューのみ）
- `public/assets/img/branding/*`：生成済みロゴ、ヒーロー、案内背景
- `public/assets/img/categories/*`：既存の**背景透過**カテゴリWebP 7枚
- `public/assets/icons/*`：外部SVG
- `app/Http/Controllers/HomeController.php`：TOPのコントローラー仮実装
- `routes/web.php`：**参考**（既存の `routes/web.php` を丸ごと置換しない）
- `preview/index.html`：視覚確認用の静的見本

## 必ず守るGunMatchのMVP仕様

- メインは個人向けの「譲る」「探す」。**ガンオク**とは異なり、欲しいものを登録して待つことができる。
- カテゴリは次の7つ：散弾銃、ライフル、ハーフライフル、エアライフル、銃身、アクセサリー、無可動銃。「その他」や曖昧な「銃」を勝手に増やさない。
- 弾薬・火薬・雷管等は取扱対象外。写真や例示としても「新着掲載」に出さない。
- メール・電話番号の認証と「所持許可あり（自己申告）」の表示を混同しない。「本人確認済み」「所持許可証確認済み」と誤認させない。
- 非会員の閲覧可。掲載やメッセージ、お気に入りはログイン後。
- トップの「譲る」「探す」の新着一覧には**実DBデータを表示**する。ただしモデル・DBが未完成の場合は空表示を維持し、実在しない出品を本番に出さない。
- TOPの検索条件は仮UI。`GET /listings` の query を検索実装時に結線。パラメータ名・カテゴリslugの変更が必要ならコード中を一括して統一する。
- 出品状況「商談中」は新規問い合わせ不可（実際の制御は詳細/メッセージ実装時に行う）。
- 銃砲等の譲渡・譲受に必要な法令・許可は当事者が満たすべきもので、GunMatchは金銭・現物を仲介しない。

## 作業順序

1. **リポジトリ確認**：既存データを保護し、最小差分で取り込み可能かを判断。
2. **Blade導入**：layout / partials / components / home / Controller / root route を統合。既存のapp layoutがあれば衝突しない命名へ調整。
3. **静的ファイル配置**：CSS/JSは別ファイル、画像はpublic配下、CSS内パスとBladeのasset()を検証。静的リソースの404がないか調べる。
4. **データ表示**：localのみサンプル表示。productionで架空データが出ないことを確認。後続のDB実装に備えてControllerからデータを渡す責務を保持。
5. **画面検証**：PC 1440px / 1024px、スマホ390px/375pxで、全体スクリーンショットを確認。ロゴ、ヒーローの文字・背景、透過画像7枚、カード、フッターを比較し、横スクロール・はみ出し・重なりを解消。
6. **機能と実装区別**：検索、ログイン、登録、掲載詳細、規約へのリンク先が未実装なら未実装と報告し、見かけだけの完成宣言はしない。
7. **検証して報告**：可能なら `php artisan route:list`、Laravelのテスト・lint、テンプレートレンダリング、レスポンシブ・表示を確認する。ユーザーへ検証を丸投げしない。

## デザインの維持条件

- 添付の参考デザインにある白基調＋深緑／ブラウン、狩猟の風景ヒーロー、写真付き7カテゴリ、新着「譲る」「探す」、案内・利用の流れ、フッターまでの構成を保つ。
- 生成済み素材を優先して使い、必要以上に再生成・差し替えをしない。
- カテゴリ写真は背景が透過された**既存WebPのまま**使う。
- ブランドカラーはCSSカスタムプロパティで管理。CSSは `public/assets/css/gunmatch.css`、JSは `public/assets/js/gunmatch.js`（将来Viteへ移行する場合もCSS/JSソースを分離）。
- UIはBladeの再利用コンポーネントとパーシャルへ分割。HTMLを巨大な1ファイルにしない。
- デザイン画像の文字を画像のまま切り貼りせず、テキスト・検索欄・ボタンはDOMで実装。

## 開発上のルール

- 必要以上の作業をしない。勝手な機能追加やMVP仕様変更はしない。
- 作業前後の差分を確認し、既存のユーザーデータ・認証実装・設定を破壊しない。
- セキュリティ上、Blade出力は `{{ }}` を使い、任意ユーザーHTMLを無加工表示しない。
- **Gitのコミットメッセージは必ず日本語**。コミット・pushはユーザーから明示指示がある場合だけ。
- 「完了」と報告する際は、実際に確認したテスト結果、未実装のURLや機能、変更ファイルを明示する。
